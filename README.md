# Fitness API — пет-проект под стажировку Python (FastAPI)

Учебный, но настоящий сервис записи в фитнес-клуб: клиенты, абонементы,
расписание тренировок и запись с проверкой бизнес-правил.

Сделан под требования стажировки Pulsea (FastAPI, Pydantic, SQLAlchemy,
PostgreSQL, pytest, Docker), но запускается локально на SQLite без установки базы.

## Что умеет

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | Панель клуба — интерфейс на русском |
| GET | `/health` | Проверка живости |
| POST | `/clients` | Создать клиента |
| GET | `/clients` | Список клиентов |
| GET | `/clients/{id}` | Получить клиента |
| POST | `/clients/{id}/memberships` | Оформить абонемент |
| GET | `/clients/{id}/memberships` | Абонементы клиента |
| POST | `/trainings` | Создать тренировку в расписании |
| GET | `/trainings` | Список тренировок с числом записавшихся |
| POST | `/trainings/{id}/bookings` | Записать клиента на тренировку |
| GET | `/bookings` | Все записи с именами клиента и тренировки |
| DELETE | `/bookings/{id}` | Отменить запись, вернуть посещение |

## Интерфейс

Открыть **http://127.0.0.1:8000/** — панель клуба на русском, без JSON:

- **Клиенты** — добавить клиента, список с телефонами.
- **Абонементы** — оформить абонемент и увидеть остаток посещений со статусом
  («Действует», «Истёк», «Посещения закончились»).
- **Тренировки** — добавить в расписание, видеть занятость мест и состояние
  («Свободно N», «Мест нет», «Прошла»).
- **Запись** — записать клиента в один клик и отменить запись; при отмене посещение
  возвращается на абонемент.

Сводка сверху показывает количество клиентов, тренировок и записей. Все ошибки
показываются всплывающим сообщением по-русски: «Нет действующего абонемента»,
«Клиент уже записан на эту тренировку» и т. д.

Техническая документация API осталась по адресу **/docs**.

## Бизнес-правила записи

Это главное, что отличает проект от учебного CRUD. При записи проверяется:

1. тренировка существует → иначе `404`;
2. клиент существует → иначе `404`;
3. тренировка ещё не началась → иначе `400`;
4. клиент не записан на неё повторно → иначе `409`;
5. есть свободные места → иначе `409`;
6. у клиента есть действующий абонемент **с остатком посещений** → иначе `403`;
7. при успешной записи остаток посещений уменьшается на 1;
8. при отмене записи посещение возвращается.

## Запуск

Нужен установленный **Python 3.12** (python.org или `winget install Python.Python.3.12`).
Проверить: `python --version` должен что-то ответить, а не открывать Microsoft Store.

### Самый простой способ

Двойной клик по **`start.bat`**. Он сам создаст окружение, поставит зависимости,
запустит сервер и откроет документацию в браузере.

### Или вручную в PowerShell

```powershell
cd fitness-api
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Активировать окружение через `activate` не обязательно — так надёжнее,
потому что не упирается в политику выполнения PowerShell.

Открыть http://127.0.0.1:8000/docs — там интерактивная документация, можно
потыкать все ручки руками. Остановить сервер: `Ctrl+C` в окне терминала.

По умолчанию база — SQLite-файл `fitness.db` рядом с проектом.

## Запуск на PostgreSQL (как в проде)

```bash
docker compose up --build
```

Поднимает Postgres и приложение на http://127.0.0.1:8000.
Строка подключения задаётся переменной `DATABASE_URL`:

```
DATABASE_URL=postgresql+psycopg2://fitness:fitness@localhost:5432/fitness
```

## Тесты

```bash
pytest -q
```

Тесты гоняют in-memory SQLite, база поднимается и удаляется на каждый тест.
Покрыты все восемь правил выше.

## Как рассказывать про него на собеседовании

Не «сделал CRUD на FastAPI», а так:

> Сервис записи в фитнес-клуб. Основная сложность была не в ручках, а в правилах:
> нельзя записаться дважды, нельзя без действующего абонемента, нельзя сверх мест,
> нельзя на прошедшую тренировку. Проверки вынес в отдельный слой сервисов,
> доменные ошибки отдаю через единый обработчик — поэтому 403/409/400 приходят
> из одного места, а не размазаны по роутам. На каждое правило есть тест.

Этот ответ показывает, что ты думаешь про бизнес-логику и тесты, а не только
про то, как вызвать `@app.get`.

## Что добавить дальше (по возрастанию сложности)

1. **Пагинация и фильтры** на `GET /trainings` — `limit`, `offset`, `date_from`.
2. **Аутентификация** — регистрация/логин, JWT, защита ручек.
3. **Alembic** — миграции вместо `create_all`.
4. **Docker Healthcheck** и запуск тестов в CI (GitHub Actions).
5. **Отмена за 2 часа до начала** — ещё одно бизнес-правило, ещё один тест.

Каждый пункт — отдельный коммит. Так в истории репозитория видно, что ты рос,
а не залил всё одним куском.
